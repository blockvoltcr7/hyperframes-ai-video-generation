# Codex Plugins — Skool lesson narration

## Plugins are capability bundles (Frame 1)

**duration_target:** 10s

    Stop thinking of a plugin as one extra tool. A Codex plugin is a reusable capability bundle—installed once, ready for an outcome.

## What lives inside a plugin (Frame 2)

**duration_target:** 17s

    Inside that bundle can be skills that teach a workflow, connectors that reach services, MCP servers that expose tools, plus browser capabilities, hooks, and scheduled-task templates.

## Install, connect, start fresh (Frame 3)

**duration_target:** 17s

    In the desktop app, open Plugins, choose one, install it, then connect the service if prompted. In Codex CLI, open slash plugins. Start a new chat or session before using newly installed capabilities.

## Outcome routing or precise invocation (Frame 4)

**duration_target:** 15s

    Then choose your level of control. Describe the outcome directly and let Codex route across installed tools—or type at and select a specific plugin or bundled skill when the source matters.

## Capability does not erase boundaries (Frame 5)

**duration_target:** 16s

    Plugins expand capability; they do not erase boundaries. Codex still follows its sandbox and approval policy. Connected services keep their own sign-in and access controls. Review permissions, especially before enabling hooks.

## The plugin practice loop (Frame 6)

**duration_target:** 15s

    Your practice loop is simple: install one plugin, connect only what it needs, start a fresh task, ask for a concrete outcome, and use at when you need precision. That is reusable workflow, not tool collecting.
